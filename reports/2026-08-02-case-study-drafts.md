## #2 LINE LLM 文（完整草稿，建議首發）

> 配圖：`reports/assets/2026-08-02/quote-line-llm.png`

客戶公司的 LINE，現在認得每一個學員 👇

背景：一家企業內訓公司（顧問業），學員遍布服務過的各家企業。以前 LINE 官方帳號只能罐頭回覆，學員問「我證書什麼時候拿到」「下一堂課在哪」都要小編人工查。

現在：LINE 接上 LLM。一般人問問題，AI 用公司的課程資料回答；**綁定過的學員問「我還差幾堂課」，系統知道他是誰、上過哪些課，直接答**。

做法一句話：LINE 官方 API + 後台學習履歷資料庫 + LLM 查詢時帶入學員上下文。

最有感的不是技術，是小編從「查資料機器」變回「處理特殊狀況的人」。

你的客服還在人工回同樣的 10 個問題嗎？

#AI應用

---（回覆串 2）---

有人問技術細節：不是把整個資料庫丟給 AI——是先驗證 LINE 身分綁定，才把「這位學員」的履歷放進上下文。權限隔離做在 LLM 外面，不是靠 prompt 拜託它別亂看。

（這類 LINE Bot + 後台系統我有在幫企業導入，需要可以聊聊）

**發布前待填**：無。此篇刻意不放具體數字，避免匿名化風險。
**技術補充（回覆串用，也是專業訊號）**：權限做在 LLM 外這句是內行話，會被懂的人轉發。

## #1 完整案例文（完整草稿，模板 F）

> 配圖：radar 卡改標題產一張「內訓公司數位化前後」或用 digest 卡列 4 個模組

我用一套系統，把一家顧問公司的 {X} 個 Excel 檔送進了資源回收桶 👇

背景:一家企業內訓公司，幫各企業開課。開課紀錄、學員名單、講師鐘點、簽到表、滿意度問卷——全部活在不同的 Excel 和紙本裡。月底對帳日就是加班日。

我的作法：一套後台整合四件事——
📋 開課與簽到（企業×課程×學員）
🎓 每位學員的完整學習履歷
⏱ 講師時數自動累計（月底薪酬直接拉報表）
⭐ 課後評分回收，講師品質有數據

結果：行政對帳從 {每月 X 天} 變成 {拉一張報表}；學員數 {級距} 的資料再也不會漏。

坑：最難的不是寫程式，是把 {X} 年的歷史 Excel 洗進資料庫——欄位格式有 {N} 種寫法。

你們公司月底也有一個「Excel 對帳日」嗎？

## #3 技術選型文（大綱）

- Hook：「客戶問我：為什麼不直接買現成的 LMS？我算了一筆帳給他看」
- 內容：現成 SaaS 的月費 ×人數×年 vs 客製一次成本；但誠實講反面——什麼情況下買 SaaS 才對
  （需求標準、人少、不想維護）。「顧問的價值是幫你選，不是永遠推自建」
- 回連：SaaS 平替特輯（nocobase 這類工具正是自建的加速器）
- 受眾是同行也是潛在客戶，誠實的選型邏輯本身就是專業展示

## #4 行政黑洞共鳴文（大綱）

- Hook：「開課的人都懂：課才兩小時，行政兩星期」
- 列訓練業的隱形成本：追簽到、算鐘點、發問卷、彙整報表、回答「我上過什麼課」
- 每項後面接一句「這個可以自動」；不提案例細節，純共鳴+暗示解法存在
- 目標：讓同業在留言區自己對號入座——共鳴文的詢單是最自然的

## #5 導入的坑（大綱，晚點發）

- Hook：「系統上線那天，才是專案的一半」
- 真實的坑：老師傅不想換工具、歷史資料要洗、流程要跟著改
- 帶出顧問價值：「賣系統的很多，陪你把人跟流程調到會用的很少」
- 這篇建立「不只會寫 code」的差異化——正是接案溢價的來源
