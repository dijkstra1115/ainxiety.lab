# Threads AI 自媒體經營策略

> 本文件是所有內容 skill 的共同依據。各 skill 產草稿時應符合這裡定義的定位、聲音與格式規則。
> 演算法相關結論來自 2026 年公開資料（文末附來源），Meta 隨時可能調整，每季回頭檢視一次。

## 一、帳號定位

**「幫你先試過的 AI 工具偵察兵」**——不是新聞台、不是課程號，是一個「每天在挖新工具、
真的動手裝來玩、然後用白話告訴你值不值得用」的開發者人設。

差異化：中文圈 AI 內容多半是「翻譯外電 + 誇大標題」。我們的護城河是三件事：
1. **有數據**：星星成長速度、實測結果，不是「聽說很強」
2. **有立場**：敢寫「這個過譽了」「落選但值得觀察」
3. **講清楚錢**：每個工具都標明要不要 API key、要不要付費——這是讀者最想知道卻最少人寫的

## 二、內容支柱（對應四個 skill）

| 支柱 | 佔比 | 互動目標 | 對應 skill |
|---|---|---|---|
| 🔭 工具雷達（清單式） | 30% | 轉發、收藏 | github-trending |
| 📰 今日 AI 短評（觀點式） | 30% | 回覆、吵架（好的那種） | ai-news |
| 🔧 實測報告（教學式） | 25% | 收藏、信任累積 | tool-deep-dive |
| 📅 週報＋預告（統整式） | 15% | 漲粉、建立追蹤習慣 | weekly-digest |

## 三、演算法要點 → 寫作規則

研究結論（來源見文末）與對應的硬規則：

1. **互動權重：回覆 > 引用 > 按讚**
   → 每則主文結尾必須有一個「低門檻提問」（「你最想試哪個？」「有人已經在用了嗎？」），
   目標是收回覆，不是收讚
2. **發文後 60 分鐘是生死線**（演算法用這段數據決定要不要推進探索頁）
   → 排程發文時間選在目標讀者活躍時段（台灣開發者：平日 09:00–10:00、21:00–23:00）；
   發文後一小時內要回覆每一條留言（這也算互動訊號）
3. **主文帶外連會被降觸及**
   → 鐵律：**所有連結放回覆串**，主文只放內容。草稿一律用
   `---（回覆串 N：連結）---` 區塊隔開
4. **單則上限 500 字元**
   → 草稿必須自帶分串。第一則負責 hook 與最強的 2–3 個點，別想塞完
5. **主題標籤可被訂閱**
   → 每則掛 1 個主題標籤（Threads 單則其實只吃一個 tag 的權重），輪用
   #AI工具 #開源 #開發者 這類有訂閱量的標籤，不要自創無人訂閱的 tag
6. **穩定頻率 > 爆量**：每週 3–5 則起跳，寧可穩定不要斷更

## 四、貼文聲音（Voice）

- 口語繁中，像跟同事聊天，不像公關稿；「我」開頭沒問題
- 數字具體化：「單週 +10,558 星」永遠比「成長超快」好
- 敢給結論：「值得裝」「先觀望」「過譽」；模糊的內容拿不到回覆
- 誠實分級：親手測過的才說「實測」；只讀了 README 的說「官方宣稱」；
  這不只是道德，是差異化定位本身
- 禁用：驚嘆號連發、「炸裂」「顛覆」「全網瘋傳」這類詞——我們的人設是冷靜的偵察兵

## 五、每週操作循環（搭配 Routines）

```
週一 09:00   github-trending  → 發「本週工具雷達」
週二 09:00   ai-news          → 發「今日 AI 短評」
週三 09:00   tool-deep-dive   → 發「實測報告」
週四 09:00   ai-news          → 發「今日 AI 短評」
週日 20:00   weekly-digest    → 發「本週回顧」＋內部產出下週選題
每次發文後 48h                 → 把洞察數據回填 metrics.json（Phase 2）
```

人工環節（刻意保留）：每天早上看 Claude 產的草稿 → 順手改一兩句加入個人觀點 → 貼上 Threads。
**草稿是 80 分起點，你的 20 分個人味才是帳號的辨識度。**

## 六、KPI（前 12 週）

| 週次 | 重點 | 指標 |
|---|---|---|
| 1–4 | 穩定產出 | 週更 ≥3 則，零斷更 |
| 5–8 | 找出爆款模式 | 單則回覆數中位數、每支柱的互動率比較 |
| 9–12 | 放大有效的 | 追蹤者成長率、最佳支柱加密度 |

前四週**不要看粉絲數**——樣本太小全是雜訊，只看「有沒有穩定出貨」。
